# 全书架构蓝图 v3：从“知识覆盖”转向“可执行、可验证、可持续演化”

> **版本截面**：2026-09-15  
> **核心变化**：v2 主要回答“最终应该覆盖哪些知识”；v3 进一步回答“这些知识怎样被代码、实验、评测、工业源码与前沿证据约束”。

# 0　重新定义项目

本项目不再只把自己定义成一本大语言模型教材，而是三位一体：

```text
                    LLM-development
                           │
        ┌──────────────────┼──────────────────┐
        │                  │                  │
        ▼                  ▼                  ▼
     TEXTBOOK         REFERENCE SYSTEM      OBSERVATORY
       教科书              可执行系统           前沿观测站
        │                  │                  │
  Theory / Math       Model Runtime        Frontier Snapshot
  History / Sources   Inference Engine     Reproduction
  Mechanism           Agent Runtime        Evaluation
  Exercises           Security             Drift Audit
        │                  │                  │
        └──────────────────┼──────────────────┘
                           ▼
                     Research Platform
```

核心约束是：

$$
\boxed{\text{Claim}\leftrightarrow\text{Code}\leftrightarrow\text{Evidence}}
$$

一个知识点即使写了很多文字，只要还没有对应实现、实验或证据，就不能因为篇幅而被视为“成熟”。

# 1　项目的真正终点

“从零构建 Astra-class / Codex-class”必须严格拆成两部分。

## 1.1　我们能从零实现的

```text
Tokenizer
→ Model Runtime
→ Weight Loader
→ Inference Engine
→ Post-training Algorithms on Small Models
→ Thread / Turn / Event Runtime
→ Tool / Protocol Runtime
→ Context / Memory
→ Planning / Verification
→ Permission / Approval / Sandbox
→ Coding Agent
→ Browser / Computer Agent
→ Multi-Agent Runtime
→ Evaluation Harness
```

这些都属于**系统与算法机制**，可以通过公开论文、官方源码、开放模型与实验验证。

## 1.2　不能假装从零复刻的

Frontier intelligence 大量存在于训练后参数 $\theta$ 中。GPT-6 Astra、Claude、Gemini、Codex 使用的前沿模型权重与完整训练 recipe 并未全部公开。

因此项目边界是：

```text
Open / Tiny Models ──→ 我们自己理解、实现、做 parity

Frontier Model APIs ─→ 可插拔 Model Backend
                           ↓
                   我们自己的 Agent/System Runtime
```

换句话说：

> **模型智能可以插拔，系统智能必须尽可能由本项目自己实现。**

# 2　七个技术层，而不是一条线性目录

## Layer A　Model Science

研究参数模型本身：

```text
Math / Probability
Tokenization / Data
Transformer / MoE
Scaling / Optimization
Post-training
Reasoning
Multimodality
Efficient / Hybrid Sequence Architectures
Diffusion Language Models
```

## Layer B　Inference Systems

研究模型如何高效执行：

```text
Reference Attention
→ SDPA / Flash kernels
→ KV / Paged KV / Prefix Cache
→ Prefill / Decode
→ Scheduler / Continuous Batching
→ Chunked / Disaggregated Prefill
→ Speculative Decoding
→ Quantization
→ Distributed Inference
→ Serving Metrics
```

## Layer C　Post-training Systems

不做 frontier-scale 训练，不等于“不写训练算法”。最终至少要运行：

```text
Tiny Pretraining
→ SFT
→ Preference Data
→ DPO
→ Reward / Verifier
→ GRPO / RLVR-style Toy Loop
→ Agent Trajectory Learning
```

目标是让论文里的 objective 变成真实 tensor、loss、trajectory 和 update。

## Layer D　Agent Kernel

核心对象不再是一个 `while model -> tool`，而是：

```text
Submission
→ Thread
→ Turn
→ Event
→ Event Store
→ Replay
→ Checkpoint
→ Resume / Fork
```

`CodexHarness.run_turn()` 只是未来 `TurnExecutor` 的一个教学实现，不应承担整个 Agent OS。

## Layer E　Environment / Protocol / Security

```text
Environment
├─ Filesystem
├─ Shell
├─ Git
├─ Browser
└─ Computer

Protocol
├─ Tool Schema
├─ MCP
├─ A2A
└─ App-Server-like Control Plane

Security
├─ Permission
├─ Approval
├─ Credential Scope
├─ Sandbox
├─ Network Policy
└─ Audit / Monitor
```

Prompt 不是安全边界。

## Layer F　Multi-Agent

不是“多个角色聊天”，而是：

```text
Task Graph
→ Scheduler
→ Worker
→ Mailbox
→ Artifact Handoff
→ Worktree / State Isolation
→ Reviewer
→ Merge
```

并且必须用单 Agent baseline 做成本与成功率对照。

## Layer G　Evaluation / Observatory

```text
Unit Test
≠ Capability Eval
≠ Frontier Evidence
```

因此三种证据分离：

```text
pytest / parity       → 实现正确性
benchmark / grader   → 能力与系统表现
frontier snapshot    → 当前行业事实
```

# 3　现实世界 2026 给项目带来的结构调整

## 3.1　从“模型”走向“长期任务系统”

前沿产品越来越强调：

```text
context management
+ tools
+ subagents
+ files / code environments
+ persistent intermediate results
+ long-running execution
```

因此 durable runtime、context system、evaluation 和 security 必须提升到 P0，而不能等到所有模型章节写完再实现。

## 3.2　从 Full Attention / Transformer 走向混合序列架构

现实路线不是简单的“Transformer 被 Mamba 替代”，而是：

```text
Full / Global Attention
+ Sparse / Local Attention
+ Linear / Recurrent State
+ KV Compression
+ MoE
        ↓
   Heterogeneous Hybrid Stack
```

第十九篇后续逐渐用可测量变量组织：

$$
\text{state bytes/token},\quad
\text{KV bytes/token},\quad
\text{FLOPs/token},\quad
\text{bandwidth},\quad
\text{retrieval precision},\quad
\text{parallelism}.
$$

## 3.3　Post-training 成为主要能力来源之一

项目不能把 SFT / DPO / RLVR 永远停在公式层。即使不做昂贵的大模型训练，也要有小规模、完整、可调试的训练闭环。

## 3.4　Long Context 不等于 Memory

最终 context system 至少分：

```text
Raw Event Log
Episodic Store
Semantic Index
Persistent Notes
Working Context
Artifact Store
Compaction Records
Retrieval Provenance
```

模型看到的每段压缩内容都应该能够追溯回原始 observation / event。

## 3.5　Multimodal 不再只是 image encoder

Astra-class 系统的 observation 最终应该是 typed multimodal object：

```text
Observation
├─ TextPart
├─ ImagePart
├─ AudioPart
├─ VideoPart
├─ DOMPart
├─ AccessibilityTreePart
├─ FilePart
├─ StructuredDataPart
└─ EnvironmentStatePart
```

# 5　P0：现在最优先

| P0 | 为什么现在做 | 验收标准 |
|---|---|---|
| Capability Manifest | 防止 README / Map / Status 再次漂移 | machine-readable + CI 校验路径、状态、证据 |
| Durable Thread Kernel | 长任务不能靠单进程内存 | 进程关闭后从 event store replay / resume |
| Event Store / Replay | 所有长期状态的事实基础 | 当前 projection 可由事件完整重建 |
| Evaluation Harness | pytest 不能测任务能力 | success / steps / tools / time / cost / verifier 统一记录 |
| Permission Enforcement | 安全不能只靠 prompt | deny 必须在 tool body 前阻断执行 |
| Real Sandbox | shell/network/browser 上线前必须有 | isolation + escape tests |
| Context Provenance | summary 不能失去证据来源 | fragment 能追溯 source event / artifact |
| Paged KV Reference | 推理系统从 toy engine 走向 serving | contiguous-vs-paged 数值 parity |

当前 v3 已经开始落地前三类工程：machine-readable manifest、event-sourced durable store、trajectory metrics 与 pre-dispatch permission gate。

# 6　P1：形成真正系统

## 6.1　Inference

```text
Paged KV
→ Prefix Cache
→ Continuous Batching
→ Chunked Prefill
→ Speculative Decoding
→ Distributed / Disaggregated Serving
```

验收统一记录：

$$
TTFT,\quad TPOT,\quad ITL,\quad throughput,\quad HBM/request.
$$

## 6.2　Post-training

```text
SFT
→ DPO
→ Verifier Reward
→ RLVR / GRPO toy system
```

必须有 loss curve、reference baseline、reward hacking case 和至少一个失败实验。

## 6.3　Protocols

```text
MCP 2026-07-28
├─ stateless request/response
├─ server/discover
├─ cacheable list semantics
├─ auth hardening
└─ Tasks / extensions

A2A 1.0
├─ AgentCard
├─ Message
├─ Task
├─ Artifact
└─ protocol bindings
```

Tool protocol、Agent protocol 与 UI/runtime control protocol 三者分离。

## 6.4　Computer Use

```text
DOM / A11y
→ Screenshot
→ Grounding
→ Mouse / Keyboard
→ State Verification
→ Cross-app Workflow
```

不能把 HTTP fetch 写成“已经有 Computer Use”。

## 6.5　Multi-Agent

统一做：

```text
1 / 2 / 4 / 8 agents
```

controlled evaluation，记录成功率、wall time、tokens、tool calls、成本、冲突、merge failure 和人工干预。

# 13　项目成功的衡量方式改变

不再主要看：

```text
Markdown file count
word count
number of model names
```

而看：

```text
validated capabilities
real parity cases
benchmark cases
reproducible experiments
security invariants
runtime recovery tests
source freshness
claim-to-code traceability
```

因此最有价值的增长应该是：

```text
30 tests → hundreds of tests
1 checkpoint family → architecture parity matrix
single request → real scheduler
single-process loop → resumable runtime
sandbox metadata → enforced isolation
unit tests → real environment eval
```
